# stage-runner: rebase onto upstream HEAD + multi-stage pipeline port

## Summary

Rebases the ik_llama stage-runner work onto the upstream pin (`fork-base`,
stock upstream HEAD `0ed847d3`), and ports the multi-stage hidden-state
pipeline driver plus the OpenAI-compatible MTP server head. This is the
first of the four staged branches that the other lanes (#53, #54, #55) stack
on.

The branch carries **16 commits** on top of stock upstream, and the working
tree is scrubbed of internal topology before publication (see below).

## What's in the branch

- **Multi-stage hidden-state pipeline** (`src/graphs/llm_stage.h`,
  `build_deepseek2.cpp`, `build_minimaxm2.cpp`): env-driven layer-window
  `[STAGE_IL_START, STAGE_IL_END)` with hidden-state emit/inject, so the model
  can be split across multiple stages (head → relay → … → tail) over TCP.
- **MTP verify head** (`mtp_msg` wire protocol + sequential verify loop): a
  direct tail→head return path with per-issue KV rollback for rejected drafts.
- **OpenAI-compatible server** (`stage-server.h`, `--role server`): an
  OpenAI endpoint on the MTP head, with prefix-cache append and a
  multi-slot pipelined mode (`--slots N>1`).
- **MiniMax-M2.7 port** + gfx1201 HIP-build fixes.
- **Launch scripts** (`examples/stage-runner/ik-server-up.sh`,
  `ik-server-pipe-up.sh`) rewritten to be **env-driven** — no hardcoded
  hosts, IPs, absolute build paths, or model names.

## Publication hygiene

- Commit messages carry **no internal hostnames, IPs, absolute build paths,
  or AI-session URLs** (see issues #51 and #55). The original "head on a
  GPU node" subject and the internal host references in the MiniMax /
  correctness-verification bodies were reworded during this rebase.
- Authorship is preserved per-commit; the identity pass (claude-dev-a →
  the public fork identity) is handled separately by the #55 mailmap step at
  GitHub-push time.
- The launch scripts read deployment values from the environment
  (`STAGE_HEAD_HOST` / `STAGE_HEAD_USER` / `STAGE_BIN` / `STAGE_MODEL` /
  `STAGE_TAIL` / `STAGE_TOKEN_RETURN` / `STAGE_RETURN_LISTEN` /
  `STAGE_IL_START` / `STAGE_IL_END`), so they are safe to publish.

## Build verification

`cmake -B build -DGGML_CUDA=ON` was run against the tree. The CPU-only
configure completes cleanly (`-- Configuring done`, `-- Generating done`,
`-- Build files have been written`), and the `llama-stage-runner` target is
generated. The `-DGGML_CUDA=ON` configure fails only because the CUDA
toolkit (`nvcc`) is not present in the build environment — the identical
failure reproduces on stock upstream `fork-base` with no CUDA toolkit, so it
is an environment limitation, not a regression in this branch.

(single-layer model files), #55 (publication gate + identity policy) stack
on top of it.
